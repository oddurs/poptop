## Problem

The tool packs braille in `src/glyphs.rs`, in Rust. The site packs braille in
`web/assets/js/frame.js`, in JavaScript. Two implementations of the encoding
that *is* the product's visual identity, with nothing comparing them.

If the tool changes how it draws — a different threshold glyph, a different
aggregation at the edges — the site keeps drawing the old poptop and calls it
poptop.

The reimplementation itself is the right call for now: the alternative to a
faithful redraw is a screenshot, and the whole argument of the hero is that a
screenshot cannot show what this tool does. What is missing is the check.

## Proposal

A golden test. The tool renders one known series to braille and emits the cells;
the site's renderer is run over the same series and asserted to produce the same
string.

Cheapest shape: a fixture file of input samples and expected cells, generated by
the tool and checked in, read by a test in `web/`. Regenerating it is a
deliberate act that shows up in a diff.

See also the wasm alternative, which removes the second implementation instead
of testing it.

## Acceptance criteria

- [ ] One fixture, generated by the tool
- [ ] A test in `web/` that fails when the two renderers disagree
- [ ] Regenerating the fixture is a visible change
